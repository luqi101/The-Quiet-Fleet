- The six reference CSVs include 251 assets, 360 devices, 8,957 jobs, 62 weather rows, 22 plan changes, and 179 support cases. The history has 640,419 envelopes, 635,066 distinct IDs, and 632,810 logical messages. The P01 key uses normalized timestamps and canonical payloads and reproduces the kit's raw-time count on this pack. Use actual inventory, indexed by keys. Keep audit totals out of runtime rules.
- The brief gives a two-minute driving position interval, a four-hour parked heartbeat, a parked late boundary strictly beyond 4 h 30 min, camera sleep 15 min after ignition-off, and a daily A check-in. Camera report cadence, wake grace, other gap tolerance, and outage thresholds require calibration. Business rules use `America/Toronto` or `America/Regina`, including Toronto’s November 1 DST transition.
- The kit startup walkthrough uses `--data data` for practice. The runner expands relative stream patterns against the scenario directory, so use an absolute path to the replay data. Preflight also mutates the live store. Practice must start from a different clean process. A runner warning or permissive validator does not relax a source requirement.
- The old tracker in P1 is marked removed in the CSV and the replacement starts reporting later. A nominal stock tracker with no asset ID reports a known VIN. The original data also contains legacy A Unix-second clocks and more distinct BX stream messages than the standalone decoder fixture. These are regression fixtures for general rules.
- Seasonal landscaping silence suggests deliberate downtime. The source provides no approval or effective dates. Keep the diagnosis provisional. The public repository was initially empty when the kit was written. Use local Git inspection as the authority for checkout history and preserve existing user files.

## Reference and event model

- Load typed asset (ID, use, type, depot, VIN, status), device (serial, family, firmware, carrier, roster assignment/status, installation date), job (asset, depot, UTC interval), weather (depot, local date, low/high), plan reference (serial, effective time, status, event ID), and case (serial/asset, observed interval, diagnosis, action/outcome) records. Build read-only maps by ID and unique VIN, an asset/depot schedule index and a depot/local-date weather index. Future schedule is valid planning context and does not establish movement. Select weather by the missed opportunity's depot and local date.
- Keep support case labels in the offline calibration path. Load CSV plan rows as reference metadata. Operational plan changes use eligible streamed receipts, since the CSV mirrors history and supplies no separate receipt timestamp. A CSV row alone contributes no evidence ID or change to empty state.
- Use one temporary on-disk SQLite store per process with one writer, bounded transactions and a consistent read snapshot. Store one logical message with serial, event type, normalized UTC observation time, time quality, canonical payload and earliest receipt. Keep original ID, receipt time and envelope provenance for each received alias. Index message time by serial/type and by receipt, and index original ID for deduplication. Copy queried facts out of the snapshot before computing rules.
- An event is available only when it has been ingested and has at least one eligible receipt at or before query `at`. Within that set, order useful facts by normalized observation time, then earliest eligible receipt and event ID for equal observation times. Accept timezone-aware clocks, supported A numeric epoch seconds and BX hex epoch seconds. Preserve raw time. An otherwise valid device event with a parseable clock ahead of its receipt retains contact provenance but cannot establish time-sensitive facts. Long positive receipt lag retains its buffering meaning.
- Enforce original-ID idempotence and semantic deduplication keyed by normalized serial/type/instant and canonical payload, excluding ID and receipt time. Use a deterministic digest and preserve the earliest eligible original alias as evidence. Retry receipts do not refresh freshness or add reboot attempts. A conflicting event ID keeps the first valid content and records a conflict. Without a usable observation time, deduplicate by exact identity only to avoid merging separate equal readings.
- Define `last_heard_at` as the latest earliest receipt of a distinct device-origin message by `at`, with `null` if unavailable. Keep observation freshness separate. Commands, plan changes and ignored types provide no device contact. Historical backfill can supply old facts on later queries without reviving current freshness. A response cites only original eligible IDs, including causal events and useful context. An explanation may have empty evidence when no such event exists. Confidence encodes evidence strength on the contract's finite 0–1 range.

## Projection, diagnosis and persona

- Treat roster status and installation date as assignment evidence. Construct effective serial–asset intervals from known VIN-bearing observations and corroborated handovers as those receipts become eligible. Retain the old tracker in earlier contexts. Resolve blank stock assignment from a known VIN where credible. Overlapping conflicting VIN claims warrant an inventory check and retain uncertainty. Use the effective tracker's assignment for same-asset ignition. A completed, documented replacement generates no permanent old-serial ticket.
- Evaluate driving and parked T separately using credible ignition and family-specific reporting deadlines. Use same-asset ignition, the prescribed sleep transition and calibrated wake/recording windows for cameras. Use elapsed time with calibrated jitter for daily devices. Within brief-supported normal states, suppress action. Confirmed cold grace requires credible battery context and is bounded. Explicit low battery or power loss takes precedence over benign explanations.
- Open power loss on a credible disconnect and close on a later credible restoration. Backup voltage and backup positions strengthen context without proving restoration. Open camera faults on storage errors or calibrated unexplained awake recording gaps. Recommend support reboot first, count unique meaningful attempts in the current awake episode and escalate to a technician after calibrated failures and grace. A later credible recording resolves the fault. Drop a paused or ended plan cause on a later effective active change. Recover low battery from later credible recovery evidence with calibrated hysteresis. Use buffering lag, signal and prior patterns for isolated coverage gaps, with bounded follow-up if recovery remains uncertain.
- Calculate overdue episodes from actual expected reporting. Cluster by carrier and depot, using comparable reporting modes for denominators. Use onset spread, minimum affected count/share and evidence of timely other-carrier peers. Exclude direct power, storage, battery, account and assignment causes and normal sleep before claiming members. Group compatible same-carrier effects into one incident, anchoring its ID to episode scope and onset. Keep its due-reporting context through prolonged gaps. Remove genuinely recovered members and close the group when fewer than two compatible affected members remain. Evaluate any remaining serial individually. Backfilled old measurements alone do not prove current recovery. Require carrier-specific contrast for a carrier attribution.
- For support, use one snapshot for status and triage. Claim incident members first and emit at most one actionable item per serial. Route group outages to carrier with one recommended customer impact update, current power and confirmed battery faults to technician, and initial camera, plan, inventory and bounded uncertainty follow-ups to support. Prioritize active job impact, broad active incidents and imminent operational deadlines under a documented provisional policy. Use half-open job intervals and the next 06:00 local shift. Sort by priority, deadline and IDs derived from the underlying episodes. Support reasons explain the observation, expectation and operational consequence.
- The chosen persona route is `/triage`. The brief's fleet and scheduler constraints remain traceable as conditional requirements in the matrix.

### P04 normal status

- Status assembles device and candidate tracker facts from one coherent receipt-time view. Roster associations are hypotheses. A date-only installation record allows the roster association from that UTC day and cannot prove the replacement was already active. An eligible unique VIN can establish a different association. A removed roster row still contributes to the period with credible activity. Live competing trackers leave camera ignition uncertain.
- T tracking uses the latest credible position in a confirmed ignition-on window through 360 seconds. Stationary positions count when ignition is on. Parked status uses the latest credible device observation through 16,200 seconds, including equality. A delayed receipt can update `last_heard_at` independently of those measurement deadlines. Future schedules do not establish ignition.
- A known compatible tracker provides the camera's ignition transition. Continued on-mode positions keep the original wake anchor. Credible sleep observed since ignition-off supports expected quiet. Silence-based sleep begins at 900 seconds when the camera has its own history. On a new ignition-on, the prior sleep context expires. Current recording is required for reporting and stays current through 600 seconds. Wake grace is inclusive through 60 seconds. A camera with uncertain tracker context can report on its own fresh recording.
- A tags use the 26-hour calibrated window, including when only one check-in is available. The reported reason separates the first missed opportunity from silence beyond one more configured daily interval. P04 uses the measured family window for all tags. Any later per-device phase estimate must be evaluated against that baseline using only eligible observations.
- Unresolved power disconnection or camera storage error prevents a benign normal state. P04 keeps those facts available for diagnosis in P05. The evaluator is pure and reusable by future triage. Confidence indicates whether eligible evidence supports a normal state.

### P05 individual diagnosis

- A documented handover with a correctly registered successor retires the former tracker only after its corroborating receipt and preserves its earlier history. Later credible activity from the former tracker can reopen a conflict. Direct VIN mismatches and competing live claims warrant support reconciliation. Camera ignition remains uncertain when competing trackers cannot establish one effective assignment.
- After the documented-removal check, direct external-power loss, storage errors, and A battery episodes take precedence. Current paused or ended plans and unresolved inventory follow, then inferred awake recording loss, approved downtime, bounded cold or coverage explanations, and normal or unknown status. Inactive plans and approved downtime defer inferred camera faults. The selected cause controls the recommendation. Other supported constraints retain their own reasons and evidence. Confidence reflects evidence strength, with stronger values for direct reports and lower values for contextual inferences.
- Power recovery requires a later credible external restoration. Backup-battery alerts corroborate a disconnection and continuing positions can show backup communication. An awake recording gap must outlast the configured deadline with credible same-asset ignition. Camera escalation requires two distinct completed awake reboot checks of 600 seconds within the current episode. Ignition-off, plan interruption, or a second command that interrupts an earlier check makes the interrupted interval inconclusive. Recording after the failure closes it. A parked asset lowers urgency. The remote-first policy uses the aggregate 28-of-40 selected-case history. The three cases on the minority firmware are too few to create a separate route.
- Plans use each named plan's latest eligible transition by observation time. A different plan's active update cannot clear a pause. A batteries open at 10% or below and recover on a strictly later reading of at least 20%. A contextual cold explanation requires an otherwise overdue A tag, its latest reading of at least 25%, and a first-overdue depot-local daily low of at most −10 °C. That grace ends after 52 hours since the reading. [Calibration evidence](calibration.md)
- Approved downtime requires the enable flag and an explicit `site_policy.downtime` record with an asset ID or use, optional depot, half-open local date interval, and written provenance. No operations reply was present, so the shipped policy has no approved windows. An overdue landscaping tag can suggest checking the seasonal schedule. Schedule absence does not establish downtime.
- Coverage follows a bounded current-drive policy. A weak modem reading in the lowest two categories and an earlier eligible buffered position can corroborate an overdue gap. Recent buffered delivery establishes transport but leaves a stale position stale. Coverage attribution expires at the configured ceiling, and ambiguous silence remains unknown. The 90-minute ceiling rounds the observed 5,396-second T delivery lag up and remains provisional. The source history supplies corroboration without a route or device allowlist. ### P06 carrier incidents

- Compare peers by effective asset depot, carrier and reporting mode. T eligibility requires demonstrated ignition-on position reporting. C eligibility requires demonstrated recording in the current unambiguous ignition-on episode. Sleep, ignition-off, approved downtime, inactive plans, unresolved registry mismatches, documented replacements, storage faults and power faults remove the relevant candidate. Parked heartbeat, A daily and BX daily observations have distinct timing and provide no driving or awake quorum.
- Five distinct overdue devices and a 50% affected share of the same eligible cohort can open a group when their missed deadlines fall within 600 seconds. A carrier attribution also requires three timely comparable devices on other carriers and 50% of that comparison cohort, with observations later than the last reports preceding the cluster. Driving and awake-camera deadlines stay at 360 and 600 seconds. One of those modes can seed a carrier episode. The other can join after its own deadline if its loss aligns with the same reporting interruption. [Threshold register](../config/rules.json) · [Calibration evidence](calibration.md)
- A broad synchronized loss across carriers or a concentrated model/firmware cluster across carriers with unrelated firmware still reporting goes to support. A later compatible cross-carrier pattern can revise a carrier interpretation when it accounts for that episode's remaining same-mode members. A single route with insufficient cross-carrier evidence retains individual uncertainty. The status is `needs_action` when a shared investigation is warranted. The cause is `carrier_outage` at evidence score 0.9 for qualifying carrier contrast or `unknown` at 0.6 for a shared interruption. These are policy scores on the contract scale.
- A UTC one-minute grid reconstructs the opening from earlier receipt cutoffs in the same committed database view. Initial confirmation or joining can wait for the next probe. The ID is derived from the opening scope, mode and deadline, and stays stable through partial recovery. On every query, current member recovery uses exact receipt and observation cutoffs. New usable positions or recordings leave the group. A report already past its allowance at receipt cannot reset the gap. Observed mode changes and direct constraints cancel eligibility. A group continues through loss of live controls and closes with fewer than two compatible members. Later episodes use new deadlines.
- Triage claims incident members before emitting current individual recommendations and validates unique ownership. ### P07 support queue

- One receipt-cutoff view supplies individual diagnoses and incident membership for both endpoints. The support queue claims the incident serials first, validates the partition, and attaches actionable individual findings for the remainder. Carrier incidents recommend one customer impact update. Unresolved power and depleted batteries go to a technician. Camera storage or awake recording faults stay with remote support until the required completed awake reboot failures. Inactive accounts, VIN conflicts, bounded coverage and actionable uncertainty stay with support.
- High priority covers confirmed reporting or service faults during a job, confirmed carrier groups with at least the configured opening count of devices still affected, and confirmed faults whose work deadline is within the provisional two-hour preparation horizon. A pending meaningful reboot stays medium if its response window ends before a future deadline. An active job or a deadline no later than the end of the response window requires immediate follow-up. Medium covers confirmed faults with later work, unresolved physical faults, and support investigations with operational risk. Nonurgent account or roster reviews, bounded coverage without imminent work, and parked camera faults without a deadline are low.
- Jobs use `[start,end)`. Active work is due now. Otherwise the deadline is the next scheduled job or the earlier 06:00 shift on that job's depot-local date. An unbooked asset has no shift deadline. Exactly 06:00 includes the current shift. The next shift is computed on the local calendar, including weekends and the two occurrences of the Toronto fall-back hour. Use the job's depot and the effective asset assignment at the query instant.
- Prolonged uncertain silence requires credible device history and an active or imminent scheduled deadline. Driving and awake camera checks use two calibrated windows. A parked or uncertain-mode tracker uses the supplied parked allowance, and a previously reporting A tag uses its daily deadline plus one daily opportunity. Expired backfill and camera booting cannot reset a known live position or recording baseline. Effective plan resumption and device power restoration start a new reporting opportunity. Follow-up remains `needs_action/unknown`, routed to support to verify service before arranging a visit. Normal reporting, expected parking or camera sleep, cold grace, and approved downtime stay quiet without an independent fault.
- Items sort by priority and deadline, then cause, assets, serials and item ID. Power, camera, plan and battery device IDs use the issue opening in observation time. Gap IDs use the missed reporting deadline, and an unresolved assignment uses the serial and effective asset. Eligible repairs can close an issue and give a later episode a new ID. Use key original evidence, a bounded set of decisive awake reboot checks, and a separate job or shift reason. Schedule rows provide deadline context.
- No operations reply was found locally. The two-hour preparation window and two fast-report windows are provisional engineering settings. The active/ended distinction, local 06:00 shifts, and calibrated family allowances are separate from those assumptions.
